# kdp-book

Fully-automated KDP book pipeline. From a single topic + book type, produces a
KDP-ready deliverable directory: print-interior PDF, wrap-cover PDF, EPUB, and
a `kdp.json` metadata package — with character-consistent illustrations
generated by `gpt-image-2`.

```bash
kdp-book generate --topic "The boy who loved chocolate"          --type children-picture-book
kdp-book generate --topic "Reincarnated into a world of fantasy" --type light-novel
kdp-book generate --topic "Python for beginners"                 --type non-fiction
kdp-book generate --topic "A detective haunted by her past"      --type fiction-novel
```

The pipeline is **resumable end-to-end**. Crash anywhere — re-run with
`--resume <slug>` and it picks up from the last completed step.

---

## Architecture

```mermaid
flowchart LR
    A[topic + type] --> B(ConceptAgent)
    B --> C(OutlineAgent)
    C --> D(BibleAgent)
    D --> E(WriterAgent)
    E --> F(EditorAgent)
    F --> G(IllustratorAgent)
    G --> H(CharacterRefRender)
    H --> I(PageImageRender)
    I --> J(CoverAgent + Compositor)
    J --> K(PDF + EPUB Builder)
    K --> L(MetadataAgent)
    L --> M(QualityAgent)
    M --> N[KDP-ready output/]
```

Each node is a `@step` in a Microsoft Agent Framework `@workflow`. State is a
Pydantic `IBookState` checkpointed to disk after every step so any failure is
recoverable.

## Install

```bash
git clone https://github.com/ShonP/kdp-book.git
cd kdp-book
uv sync
cp .env.example .env  # then fill in your keys
uv run kdp-book --help
```

### `.env`

```ini
AZURE_API_KEY=sk-...
OPENAI_BASE_URL=https://your-azure-endpoint.openai.azure.com/openai/...
AZURE_IMAGE_ENDPOINT=https://your-azure-endpoint.cognitiveservices.azure.com/openai/deployments/gpt-image-2/images/generations?api-version=2024-02-01

# Optional overrides
MODEL=gpt-5.5
IMAGE_QUALITY=low                # low|medium|high
IMAGE_SIZE=1024x1024             # 1024x1024 | 2048x2048
IMAGE_GENERATION_WORKERS=3       # parallel image renders
CHAPTER_WRITER_WORKERS=3         # parallel chapter drafts
KDP_AUTHOR_NAME="Your Pen Name"
KDP_BOOKS_DIR=books
```

## CLI

| Command                                | What it does                                                         |
| -------------------------------------- | -------------------------------------------------------------------- |
| `kdp-book generate --topic ... --type` | Run the entire pipeline. `--resume <slug>` to recover.               |
| `kdp-book outline  --topic ... --type` | Concept → outline → bible only. Cheap design pass before committing. |
| `kdp-book write    --slug ...`         | Draft chapters from saved outline.                                   |
| `kdp-book illustrate --slug ...`       | Generate scene briefs (no rendering).                                |
| `kdp-book step <name> --slug ...`      | Re-run any single step (`bible`, `write`, `images`, `cover`, ...).   |
| `kdp-book cover    --slug ...`         | Re-render front + back + wrap.                                       |
| `kdp-book format   --slug ...`         | Compile PDF + EPUB from current chapter+image state.                 |
| `kdp-book metadata --slug ...`         | Generate KDP `kdp.json` (title, description, keywords, BISAC).       |
| `kdp-book quality  --slug ...`         | Run final review (originality + KDP compliance).                     |
| `kdp-book doctor`                      | Verify `.env` keys + endpoints + model availability.                 |
| `kdp-book ls`                          | List existing book directories.                                      |

### Quality override

```bash
# Default is low (fastest + cheapest)
kdp-book generate --topic "..." --type children-picture-book --quality high
```

## Book types

| Type                    | Pages   | Trim     | Illustrations           | Notes                                |
| ----------------------- | ------- | -------- | ----------------------- | ------------------------------------ |
| `children-picture-book` | 24–32   | 8.5×8.5" | full-page, every scene  | large text, vivid color, no profanity |
| `light-novel`           | 200–300 | 5×8"     | chapter splash + 2 inserts | manga/anime aesthetic                |
| `non-fiction`           | 100–200 | 6×9"     | diagrams, code blocks   | citations, references                |
| `fiction-novel`         | 200–400 | 6×9"     | chapter art only        | longer-form prose, deeper editing    |

Each type has a `BookTypeConfig` (`models/book.py`) that pins page count, trim
size, paper type, image size, illustrations-per-chapter, etc. Configs are
swappable — adding a new type is a single Pydantic model.

## Character consistency

Ported from the `mangas/` repo. Each book has its own asset registry. The flow:

1. **BibleAgent** produces a structured `BookBible` with one entry per
   *individual* character (`Pip`, `Luna`, `Captain Finn`). Plurals/groups
   ("Children", "Young Dragons", "The Villagers") are forbidden by prompt and
   filtered post-hoc.
2. **CharacterRefRender** renders one **default sheet per character** with
   `gpt-image-2`. Each character lives in its own directory:

   ```
   books/<slug>/assets/
   ├── Ember/
   │   ├── default.png
   │   ├── default.png.json     # sidecar: prompt, model, refs, retries
   │   └── variants/
   │       ├── side.png
   │       └── angry.png
   └── Luna/
       ├── default.png
       └── variants/
           └── running.png
   ```
3. **PageImageRender** edits each page using `gpt-image-2`'s edit-with-refs
   mode. For every named character in the scene the renderer resolves the
   right variant from the registry and includes it as a reference image, so
   "Ember" looks like Ember in every panel.
4. **AssetRegistry** keeps a `manifest.json` mapping character → variants →
   on-disk paths. Variants can chain (`angry` derived from `default`) and be
   marked `stale` when a parent variant is regenerated.

## Parallelism

`asyncio.gather` + `asyncio.Semaphore` parallelizes the slow steps:

- Character reference sheets (`IMAGE_GENERATION_WORKERS`, default 3)
- Page illustrations (same pool)
- Chapter drafting (`CHAPTER_WRITER_WORKERS`, default 3)

A 14-page picture book that took ~30 minutes serially renders in ~10
minutes with 3 workers. Set workers to `1` if you want strictly sequential
runs (e.g. for novel chapters where prose-tail continuity matters).

## Cost estimates

Live-verified. Defaults: `gpt-5.5` ($5/M input + $15/M output) and
`gpt-image-2` at `quality=low`, `1024×1024`.

| Type                    | Tokens (text) | Images        | Approx. cost |
| ----------------------- | ------------- | ------------- | ------------ |
| `children-picture-book` | ~80k          | 4 chars + 14 pages + cover | **~$2.00**   |
| `light-novel`           | ~600k         | 8 chars + 30 inserts + cover | **~$10.00**  |
| `non-fiction`           | ~250k         | cover + diagrams (text-mostly) | **~$3.00**   |
| `fiction-novel`         | ~700k         | 6 chars + 12 chapter art + cover | **~$8.00**   |

Bumping `--quality high` ~4× the image cost. Text-only (`--no-images`)
strips ~80% of the bill.

Every run produces:

- `books/<slug>/run_metadata.json` — totals (tokens, cost, duration, steps)
- `books/<slug>/metadata/<NN>_<step>.json` — per-step detail (prompts,
  outputs, retries, model)
- `books/<slug>/<image>.png.json` — per-image sidecars (prompt, refs,
  safety filter hits, generation time)

## Output

After a successful run, `books/<slug>/output/` contains:

```
output/
├── interior.pdf       # KDP print interior (trim, bleed, gutter, margins)
├── interior.epub      # KDP EPUB
├── cover.pdf          # full wrap (back + spine + front)
└── kdp.json           # title, subtitle, description, keywords, categories,
                       # BISAC codes, age range, language, price suggestions
```

That's the whole package — drop it into KDP's "Add new title" flow.
